# Отчет о тестировании PWA «Валка деревьев — ГЭСН 01/47»

**Версия:** 1.0.0  
**Дата проверки:** 29.08.2026  
**Предмет проверки:** расчетный алгоритм, интерфейс desktop/mobile, формирование документов, структура PWA и локальная раздача файлов.

## 1. Итог

Автоматические проверки завершены успешно. Критических ошибок в расчетной логике, маршрутизации интерфейса и формировании документов не выявлено.

Контрольный демонстрационный сценарий дал ожидаемый результат:

- всего деревьев — 5;
- валка целиком, ГЭСН 01-02-099 — 2;
- поэтапное спиливание, ГЭСН 47-01-128 — 2;
- норма не определена — 1;
- готовность исходных данных — 80 %.

## 2. Синтаксическая проверка

Команда:

```bash
npm run check
```

Проверены `domain.js`, `storage.js`, `templates.js`, `app.js`, `sw.js`. Ошибок синтаксиса не обнаружено.

## 3. Модульные тесты расчетного алгоритма

Команда:

```bash
npm test
```

Результат: **15 из 15 тестов пройдены**.

Проверены сценарии:

1. выбор ГЭСН 01 и поднормы по диаметру для валки целиком;
2. выбор ГЭСН 47-01-128-01 для твердолиственного дерева до 0,5 м;
3. отнесение лиственницы свыше 0,5 м к соответствующей поднорме ГЭСН 47;
4. выявление противоречия при валке целиком и препятствии в секторе падения;
5. требование отдельного обоснования при невозможности валки без объективного препятствия;
6. формирование перечня незаполненных обязательных полей;
7. замечание при отсутствии подтверждения возможности установки подъемника для ГЭСН 47;
8. замечание, если свободная зона короче высоты дерева при ГЭСН 01;
9. отдельное предупреждение по безопасности для аварийного дерева;
10. блокировка несуществующей поднормы для диаметра более 64 см без сжигания;
11. выбор последней предусмотренной поднормы при сжигании мягкой породы свыше 32 см;
12. исключение из заключения категорий с нулевым количеством;
13. корректный короткий текст для пустого реестра;
14. корректный подсчет трех итоговых категорий;
15. формирование всех четырех документов из одного реестра.

## 4. Интерфейсное тестирование desktop и mobile

Команда:

```bash
npm run test:ui
```

Проверка выполнена в Chromium в двух размерах:

- desktop: 1440 × 1000;
- mobile: 390 × 844 с сенсорным режимом.

Успешно проверены:

- загрузка демонстрационного объекта;
- отображение четырех итоговых показателей;
- переходы между главной страницей, объектом, реестром, документами, требованиями и настройками;
- отображение пяти карточек демонстрационного реестра;
- открытие редактора существующего дерева;
- живой автоматический пересчет нормы;
- создание и сохранение нового дерева по ГЭСН 01;
- увеличение реестра с 5 до 6 карточек;
- поиск по номеру дерева;
- формирование акта, технического решения, ПОС и ППР;
- наличие норм ГЭСН в сформированных документах;
- отображение требований к проектировщику;
- доступность экспорта JSON;
- редактирование наименования объекта;
- видимость мобильных кнопок изменения, копирования и удаления карточки;
- отсутствие ошибок JavaScript в консоли и необработанных ошибок страницы.

Контрольные снимки находятся в папке `screenshots`.

## 5. Проверка структуры PWA

Команда:

```bash
npm run test:pwa
```

Успешно проверены:

- корректность JSON-файла `manifest.webmanifest`;
- режим `standalone`;
- `start_url` и `scope`;
- наличие и фактические размеры иконок 192 × 192 и 512 × 512;
- наличие обработчиков install, activate и fetch в service worker;
- наличие всех 11 файлов офлайн-оболочки;
- ссылки на manifest, CSS, JavaScript и иконку из `index.html`.

## 6. Проверка локальной раздачи

Приложение запущено командой:

```bash
python3 -m http.server 8765
```

Для `index.html`, CSS, manifest, service worker, всех JavaScript-модулей и иконок получен HTTP-статус **200**.

## 7. Исправление, выполненное по результатам тестирования

В исходном мобильном представлении пиктограммы действий карточки наследовали прозрачный цвет текста. Разметка кнопок была переработана: пиктограммы вынесены в отдельные элементы, добавлены доступные подписи `aria-label`, а мобильные стили скорректированы. Повторный desktop/mobile-тест выполнен успешно.

## 8. Что требует проверки на реальном устройстве

Автоматизированная среда не воспроизводит полностью аппаратные и системные функции телефона. Перед промышленным применением необходимо выполнить приемочную проверку:

- установки с фактического HTTPS-домена;
- работы service worker после физического отключения сети;
- разрешений камеры и геолокации;
- качества и размера фотографий с используемых телефонов;
- сохранения данных после перезагрузки устройства;
- системного диалога печати и сохранения PDF;
- доступного объема IndexedDB в корпоративном браузере;
- поведения при обновлении опубликованной версии приложения.

Указанные пункты относятся не к найденным дефектам, а к функциям, зависящим от конкретного устройства, браузера, политики безопасности и HTTPS-хостинга.
